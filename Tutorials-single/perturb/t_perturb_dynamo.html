In-silico perturbation with dynamo’s vector field#

The dynamo backend of ov.single.perturb uses dynamo.pd.perturbation to propagate a target-gene expression change through a learned PCA vector field. The default j_delta_x method uses its analytical Jacobian:

\[\delta Y = J \cdot \delta X.\]

The per-cell, per-gene response and perturbation transition matrix are returned as a PerturbResult for downstream analysis and visualization. This tutorial uses dynamo’s processed hematopoiesis reference data to simulate knockout of the erythroid transcription factor GATA1.

This backend requires velocity-compatible data and a learned vector field, or raw splicing/labeling measurements from which dynamo can estimate them. backend='auto' selects dynamo when adata.uns['VecFld_pca'] is present. Choose a backend explicitly when selecting a different model.

Requirements#

Install OmicVerse and the optional dynamo backend in the same Python environment:

python -m pip install 'dynamo-release==1.5.3' 'numpy<2'

The examples use dynamo-release 1.5.3. The processed dataset is downloaded on its first use; the raw-data example requires a separately downloaded file.

Knockdown (KD) and over-expression (OE)#

For each target, KD sets expression to its mean divided by fold_change; OE sets it to its mean multiplied by fold_change. Each target has a common requested level across cells, rather than each cell being scaled independently. The mean comes from the selected layer, or adata.X by default, on the expression scale used for PCA.

perturb_mode='z_score' converts this requested level using dynamo’s PCA-reconstructed gene distribution. A constant reconstructed distribution cannot be converted; use perturb_mode='raw' in that case.

Use copy=True to retain independent results. Each result’s response layers and group tables belong to its adata_perturbed object.

result_kd = ov.single.perturb(
    adata, target='GATA1', mode='kd', fold_change=2.0,
    backend='dynamo', copy=True,
    backend_kwargs={'group': 'cell_type', 'add_delta_Y_key': 'gata1_kd_response'},
)
result_oe = ov.single.perturb(
    adata, target='GATA1', mode='oe', fold_change=2.0,
    backend='dynamo', copy=True,
    backend_kwargs={'group': 'cell_type', 'perturb_mode': 'z_score',
                    'add_delta_Y_key': 'gata1_oe_response'},
)
print('KD / OE shapes:', result_kd.delta_X.shape, result_oe.delta_X.shape)

3. Interpret the response and transition outputs#

result.delta_X is the per-cell, per-gene model response. result.trajectory_shift is dynamo’s cell-to-cell perturbation transition matrix. Its rows should sum to one. These outputs support the transition summary and embedding arrows shown below.

For dynamo, result.adata_perturbed contains the input object or its copy, with response layers and projection outputs added. Its .X remains the baseline expression, possibly preprocessed by auto_pipeline; it is not replaced by predicted post-perturbation expression.

Interpretation

Signed model response for each cell and gene

result.adata_perturbed.layers[result.meta['perturbation_key']]

The same native gene-response matrix

result.delta_expr['delta']

Mean signed response across cells

mean_base / mean_pert

Baseline mean / baseline mean plus model response; the latter is a derived summary, not fitted counts

log2_fc

Response-derived log ratio with pseudocount 1e-6; NaN when either mean is negative or non-finite

result.grn, result.grn_base

Always None; dynamo does not reconstruct a GRN through this interface

result.delta_grn

Empty, including when grn_output=True

6. Vector-field knockout: vf_ko=True#

vf_ko=True additionally evaluates dynamo’s native KO vector field and writes velocity_pca_KO / velocity_umap_KO, with corresponding coordinate copies X_pca_KO / X_umap_KO. The baseline PCA and vector field are preserved.

KO velocities are stored separately. result.delta_X, result.trajectory_shift, group rankings and shared downstream plots retain the interpretation of the selected perturbation method (Jacobian by default). Callable KO models and fate integration require separate use of dynamo’s native KO interface.

The option applies to mode='ko'. KD/OE emit a warning and do not perform the additional vector-field knockout. Use copy=True for independent results, or distinct output keys for multiple runs on one AnnData.

Active KO reserves X_pca_KO, velocity_pca_KO, X_<emb_basis>_KO and velocity_<emb_basis>_KO in obsm, and pearson_transition_matrix in obsp. Custom perturbation output keys that collide with these names raise ValueError before computation. Use distinct names such as gata1_vf_ko_response and gata1_vf_ko_transitions.

The following example uses copy=True and reads KO outputs from result_ko.adata_perturbed.

Native KO requires the default PCA coordinates/loadings/means and VecFld_pca. A cached Jacobian or custom PCA alone is insufficient; prepare the default KO model or leave vf_ko=False.

result_ko = ov.single.perturb(

    backend_kwargs={'vf_ko': True, 'group': 'cell_type',
                    'add_delta_Y_key': 'gata1_vf_ko_response'},
)
print('KO velocity keys written:', result_ko.meta['vf_ko_keys'])

Prepare the model explicitly#

For raw data indexed by gene symbols, the corresponding preparation is:

import dynamo as dyn

preprocessor = dyn.pp.Preprocessor(
    convert_gene_name_function=lambda data: data,
    gene_append_list=['GATA1'],
)
preprocessor.preprocess_adata(adata, recipe='monocle')
dynamics_kwargs = {}
preprocessing = adata.uns.get('pp', {})
if (preprocessing.get('experiment_type') == 'kin'
        and preprocessing.get('has_splicing')
        and not preprocessing.get('splicing_labeling')):
    dynamics_kwargs['est_method'] = 'twostep'
dyn.tl.dynamics(adata, **dynamics_kwargs)
dyn.tl.neighbors(adata, X_data=adata.obsm['X_pca'], basis='pca')
dyn.tl.reduceDimension(
    adata, X_data=adata.obsm['X_pca'], basis='pca',
    n_pca_components=adata.obsm['X_pca'].shape[1], reduction_method='umap',
)
dyn.tl.cell_velocities(adata, basis='pca', enforce=True)
dyn.vf.VectorField(adata, basis='pca')
result = ov.single.perturb(adata, target='GATA1', mode='ko', backend='dynamo')

All targets must have use_for_pca=True; multi-target values are aligned in PCA gene order. The selected input layer must use the PCA model’s expression scale.

Native parameter access and compatibility#

The backend adapts dynamo.pd.perturbation; it does not replace the entire dynamo API. target corresponds to native genes. Without an explicit expression, KO/KD/OE generate the requested levels described above. A finite scalar or one value per unique target can override those levels:

result_custom = ov.single.perturb(
    adata, target=['GATA1', 'HBB'], backend='dynamo', copy=True,
    backend_kwargs={'expression': [0.0, 1.5], 'perturb_mode': 'raw',
                    'cells': [0, 1, 2]},
)

Values follow the caller’s target order and use native raw or z_score units. An explicit z-score is passed directly; automatic KO/KD/OE levels are converted from expression units. mode remains the result label and controls additional vf_ko; inspect meta['expression_source'] and meta['expression'] for the actual requested levels.

Behavior

cells

Restrict the perturbation to selected cell indices

pca_key, PCs_key, pca_mean_key, X_pca

Custom PCA inputs are reused without requiring default PCA keys. With explicit X_pca, omitted loading/mean options resolve to PCs / pca_mean. The automatic pipeline fits the default PCA model; prepare a custom model’s missing prerequisites explicitly instead of requesting an automatic refit.

Dynamo-release 1.5.3 has several native limitations:

  • Its precomputed delta_Y path leaves PCA loadings undefined. This option raises NotImplementedError here; use target/expression perturbations.

  • pca_key must be a string. Pass coordinate arrays as X_pca instead.

  • Native target-zeroing uses PCA-local indices on full-gene response layers. The wrapper rejects zero_perturb_genes_vel=True if those indices differ, preventing unrelated genes from being silently zeroed.

  • projection_method='transform' can reload baseline velocities rather than the perturbation response. It emits a warning and returns no transition matrix. Prefer fp for perturbation-driven transitions and arrows.

group and vf_ko provide the ranking and KO defaults shown in this tutorial. For custom ranking aggregation, gene selection or output prefixes, call dynamo.pd.rank_perturbation_genes directly. For custom KO vector fields, output names, velocity differences, model persistence or callable KO models, use dynamo.pd.KO directly. Fate integration remains a separate native workflow.

Full raw-data example#

The raw hematopoiesis file contains 1,947 cells and 26,193 genes, with spliced/unspliced and new/total counts and sampling times in obs['time']. Its gene index contains Ensembl IDs. Download it to the working directory or adjust the path below. The example starts a fresh AnnData with every input cell and gene:

import anndata as ad

source = ad.read_h5ad('hematopoiesis_raw.h5ad')
raw = ad.AnnData(
    X=source.X.copy(), obs=source.obs.copy(), var=source.var.copy(),
    layers={key: source.layers[key].copy()
            for key in ('spliced', 'unspliced', 'new', 'total')},
)
result_raw = ov.single.perturb(
    raw, target='ENSG00000102145', mode='ko', backend='dynamo',
    backend_kwargs={'auto_pipeline': True, 'group': 'cell_type'},
)
print(result_raw.delta_X.shape, result_raw.trajectory_shift.shape)
print(result_raw.meta['dynamics_est_method'])

Native preprocessing still performs quality control and PCA feature selection. Use mode='kd' or mode='oe' with fold_change for knockdown or over-expression. With mode='ko', add vf_ko=True to request KO velocities.

Responses depend on the input data, preprocessing and vector-field fit. Refitting may change response amplitudes and gene rankings; interpret them with cell-type annotations, experimental design and biological evidence.

8. Frequently asked questions#

Why is dynamo selected automatically?#

VecFld_pca takes priority over a base GRN in backend='auto'. Select backend='cell_oracle' or backend='sctenifoldknk' explicitly to use those models.

Why is a target missing or excluded from PCA?#

Match target exactly to adata.var_names, including Ensembl IDs when applicable. A fitted PCA model must include all targets in use_for_pca. If a target is excluded, refit PCA and the vector field with that target included; changing the feature flag alone does not update the fitted model.

Can expression counts alone run the automatic pipeline?#

No. Provide splicing or metabolic-labeling count layers and the sampling information required by the experimental design. For expression-only data, select backend='sctenifoldknk'. With auto_pipeline=False, missing model prerequisites raise a RuntimeError listing preparation steps.

Where are predicted expression and GRN outputs?#

Dynamo returns model responses in delta_X and the named response layer. It does not replace .X with predicted counts or reconstruct a GRN. grn / grn_base are None, and delta_grn is empty.

Why is log2_fc sometimes NaN?#

mean_pert is baseline mean plus signed model response and may be negative. The response is retained, but its fold-change summary is undefined when either mean is negative or non-finite. Rank such genes by delta or the absolute-response group table instead.

Why do group tables omit genes or change the ranking?#

Native rankings include use_for_dynamics genes. Signed rankings use the mean response; absolute rankings use the mean absolute per-cell response. These summaries answer different questions and can order genes differently.

How can multiple runs be retained?#

Use copy=True and read outputs from each result’s adata_perturbed, or choose distinct add_* keys on a shared object. Active vf_ko reserves the native KO output names described above; conflicting keys raise ValueError.

Why is the transition matrix missing, or KO ignored?#

projection_method='transform' produces no transition matrix and can use baseline velocities in 1.5.3; prefer fp for perturbation-driven arrows. vf_ko=True adds native KO velocities only in KO mode; KD/OE warn and skip that additional calculation. Shared response and transition outputs remain the selected perturbation results (Jacobian by default).

Summary#

  • KO/KD/OE responses and the native transition matrix are available through PerturbResult.

  • The baseline .X is preserved; read delta_X or the named response layer for model responses. GRN outputs are unavailable for dynamo.

  • Shared response analyses include cell-type transitions, embedding arrows and perturbation scores. Additional KO velocities are stored separately.

  • Automatic dispatch selects dynamo for VecFld_pca, CellOracle for a base GRN, and scTenifoldKnk otherwise.

  • Automatic fitting requires count layers and sampling information compatible with the experimental design; gene identifiers and expression scales must match the model.
