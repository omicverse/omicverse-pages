Multi-site harmonization with traveling subjects#

Quantitative read-outs that are pooled across sites, scanners, instruments or assay platforms — MRI imaging-derived phenotypes (regional volumes, cortical thickness, QSM susceptibility, diffusion FA/MD), radiomic features, plate-reader or immunoassay values — carry a device offset: the same person measured on two scanners gives two different numbers. If the case/control mix also differs between sites (one hospital recruits mostly patients, another mostly controls), the device offset and the biology are confounded, and a naive pooled analysis reports scanner differences as disease effects.

The cleanest way to separate the two is a traveling-subject (a.k.a. “travelling phantom / human phantom”) design: a small cohort of the same healthy people is measured on every device. Because the subject is identical, any difference between devices on that subject is the device. ov.bulk provides three functions for this design:

Function

What it does

ov.bulk.multisite_harmonize

fits the two-way subject + device model on traveling-subject data and returns one additive offset per device and feature, shrunk with empirical Bayes along the device hierarchy (scanner → model → vendor)

ov.bulk.apply_multisite_harmonization

applies the frozen offsets (corrected = raw + offset) to any new rows — the site-local cohorts — with fallbacks for devices that were never in the fit

ov.bulk.predict_device_offsets

predicts the offset of an unseen device from its acquisition metadata (field strength, voxel size, software …) by empirical-Bayes kriging within its parent (vendor)

Principle. For a feature, the equal-weight mean of subject s on device d is modelled as

\[\bar y_{sd} = \mu_s + \beta_d + \varepsilon_{sd}.\]

The subject term \(\mu_s\) absorbs everything biological, so \(\beta_d\) is only the device. Subjects need not visit every device — the design only has to be connected (every device reachable from every other through shared subjects). With few traveling subjects the OLS \(\hat\beta_d\) are noisy, so they are shrunk — not toward zero, but toward the parent: a scanner toward its model, a model toward its vendor, a vendor toward the global mean, each with a method-of-moments variance component \(\tau_b^2\) (pooled within user-given feature families). Offsets are centred over devices: the harmonized scale is the average device.

When to use it. Whenever you have traveling subjects (or phantoms, or a bridging reference sample run on every platform). If you do not, you have to fall back on ComBat-type methods that estimate the site effect from the site-local data themselves — and must then model the biological covariates correctly (section 5 shows why).

This tutorial simulates a realistic study with a known ground truth, so every estimate can be checked.

1. Simulate a multi-vendor study with traveling subjects#

Eight MRI scanners from two vendors, two scanner models per vendor, two scanners per model. Each scanner has acquisition parameters (field strength, voxel size, software major version). The true device effect on each of 40 features is built hierarchically:

  • a vendor effect (large),

  • a model-within-vendor effect (medium),

  • a scanner deviation that depends smoothly on the voxel size (partial-volume effects do exactly this) plus a small idiosyncratic term.

The 40 features come in two families with different noise levels — 20 “volumetric” and 20 “diffusion” phenotypes — which we will pass as feature_groups so that variance components are pooled within each family.

rng = np.random.default_rng(7)

Traveling subjects. Fifteen healthy volunteers; twelve form the training panel and each visits a random subset of five or six scanners (some with a repeat scan) — an unbalanced but connected design, as in real traveling-subject studies where not everyone can travel everywhere. fit['offsets'] is a scanners × features table; a harmonized value is raw + offset, i.e. the measurement re-expressed on the scale of the average scanner. fit['effects'] holds the same numbers with the opposite sign (the device effect). Other entries worth knowing:

  • fit['ratios'] — the shrinkage strength \(\sigma^2/\tau_b^2\) of each hierarchy block (large = that level shows little real spread beyond noise, so it is pulled hard toward the parent);

  • fit['fallback_offsets'] — mean offsets per model and per vendor, used for devices that were never in the fit;

  • fit['residual_variance'] — the per-feature noise \(\sigma^2\) left after the two-way model.

3. Apply the offsets to held-out traveling subjects#

The three test volunteers were scanned on all eight scanners but never used in the fit. Their between-scanner spread is pure device effect plus noise, so it is the most direct test of a harmonization: after correction, the same person should give the same number everywhere (down to the measurement noise).

4. Harmonize the site-local cohorts#

def pca2(X):
    Xc = X - X.mean(0)
    U, S, Vt = np.linalg.svd(Xc, full_matrices=False)
    return Xc @ Vt[:2].T, (S[:2] ** 2 / (S ** 2).sum())

A quantitative version: the fraction of each feature’s variance explained by the scanner (one-way \(R^2\)), computed within controls only so that the confounded disease does not contribute.

def site_r2(df):
    ctrl = df[df.group == "control"]
    tot = ctrl[features].var(ddof=0)
    within = ctrl.groupby("scanner_id")[features].transform(lambda x: x - x.mean()).var(ddof=0)
    return 1 - within / tot

ax.set_xticks([0, 10, 20, 30]); ax.set_xticklabels(["vol_00", "vol_10", "dti_00", "dti_10"])
ax.set_ylabel("patient − control"); ax.legend(frameon=False, ncol=4, fontsize=8, loc="lower right")
ax.set_title("Disease effect per feature")
plt.tight_layout(); plt.show()

  • Raw pooled (grey): because patients are over-represented at vendor A, every vendor A−B difference leaks into the patient–control contrast — the null features show spurious “effects” as large as the real one.

  • Site-mean centring (red): removing each site’s mean removes the site effect, but the site mean also contains the site’s patient fraction, so part of the real disease effect is removed with it — the true effect is attenuated (biased toward 0). With prevalences of 85 % vs 15 % the expected pooled estimate is only about half of the truth (\(1 - (\bar p_{\text{cases}} - \bar p_{\text{controls}}) = 1 - (0.745 - 0.255) \approx 0.51\)), while the null features look clean — a silent, not a visible, failure.

  • Traveling-subject harmonization (blue): the offsets come from people whose biology is held fixed across scanners, so they contain no disease signal; the real effect is recovered without bias and the null features scatter around 0.

Note the price: the harmonized estimates are not noise-free. Each offset is estimated from a dozen traveling subjects, and that estimation error (fit['offset_variance']) propagates into every corrected value — visible as the spread of the blue points around the truth. More traveling subjects, or repeat scans, shrink it; a biased estimate does not get better with more patients.

5. A contrast with ComBat#

ComBat (ov.bulk.batch_correction, a wrapper of pyComBat) estimates the batch location and scale from the site-local data themselves, with an empirical-Bayes prior across features. Without covariates its location step is essentially the site-mean centring above, so it inherits the same attenuation under confounding. ComBat can protect biology if the covariate (here, diagnosis) is put in the model — neuroComBat does this — but then (i) every biological variable you later want to test must be known and modelled at harmonization time, and (ii) when the confounding is severe (a site with almost only patients) the site and disease terms become nearly collinear and both are estimated poorly. Traveling subjects avoid the problem by design: the offset is measured on people whose biology does not change.

The two approaches are complementary: when you have traveling subjects, use them for the offsets; when you have none, use ComBat with the biological covariates and check the confounding table (section 1) first.

6. A scanner that was never in the traveling-subject study#

Sites upgrade software, replace coils or join late. Suppose a new vendor-A scanner A2-c (model A2, 1.5 T, voxel 1.25 mm, software 11) joins and only scans local subjects. Three options for its offset:

  1. no correction;

  2. the parent mean — the average offset of the trained A2 scanners (fit['fallback_offsets']['scanner_model'], what apply_multisite_harmonization uses when it knows only the model);

  3. predict_device_offsets — kriging within the parent on the acquisition parameters: the new scanner borrows most from trained scanners with similar parameters (here A2-b, voxel 1.3 mm).

7. Pitfalls#

  • Additive model. The offsets are additive on the scale you pass in. If a device effect is multiplicative (e.g. volumes scaling with a gradient-calibration error), harmonize log values and back-transform.

  • Connectivity. The subject–device graph must be connected; otherwise the offsets of two disconnected groups of scanners are not comparable and the function raises.

  • Traveling subjects should span the population range. The model assumes the device effect does not depend on the subject (no subject × device interaction). If the device effect differs for, e.g., atrophied brains, a healthy-only panel cannot learn it.

  • The hierarchy must nest. A level that varies within a device or is not nested in the next coarser level is dropped with a warning — read the warnings.

  • Unseen devices. Without metadata, unseen devices get the parent mean, and the function warns. Give new_device_table / device_table whenever a protocol sheet exists.

  • Freeze the fit. Fit once on the traveling subjects, then apply the same frozen offsets to all cohorts; never refit on the clinical data, which would reintroduce the confounding.

  • Uncertainty. fit['offset_variance'] gives the sampling variance of each offset; with very few traveling subjects it can be comparable to small disease effects.
